PHASE 1: PRÉPARATION (5 min)
════════════════════════════════════════════════════════════════════════════

□ Sauvegarde du projet actuel
  $ cp -r /var/www/html/saas /backup/saas-backup-$(date +%Y%m%d)

□ Extraction du projet livré
  $ unzip projet-saas-updated.zip -d /tmp/

□ Copie des fichiers sources
  $ cp -r /tmp/projet-saas-updated/src/* src/
  $ cp -r /tmp/projet-saas-updated/public/assets/* public/assets/
  $ cp -r /tmp/projet-saas-updated/templates/emails/* templates/emails/

□ Vérification de la structure
  $ find src/ -name "*.php" | wc -l
  $ find templates/ -name "*.twig" | wc -l


PHASE 2: DÉPENDANCES PHP (2 min)
════════════════════════════════════════════════════════════════════════════

□ Vérifier composer.json (devrait être OK)
  $ composer show | grep -i "mailer\|console"

□ Si nécessaire, installer:
  $ composer require symfony/mailer symfony/console


PHASE 3: MIGRATIONS DOCTRINE (10 min)
════════════════════════════════════════════════════════════════════════════

□ Générer les migrations
  $ bin/console make:migration
  → Accepter les changements pour:
    - DocumentTemplate (nouvelle entité)
    - Invoice.reminderSentAt (nouveau champ)

□ Vérifier les migrations générées
  $ ls -la migrations/ | tail -5
  → 2 nouveaux fichiers de migration

□ Exécuter les migrations
  $ bin/console doctrine:migrations:migrate

□ Vérifier le schéma
  $ bin/console doctrine:schema:validate
  → Message: "The mapping file is valid"


PHASE 4: CSS & JAVASCRIPT (2 min)
════════════════════════════════════════════════════════════════════════════

□ Vérifier les fichiers sont en place
  $ ls -la public/assets/styles/dark-mode-responsive.css
  $ ls -la public/assets/js/dark-mode-responsive.js

□ Mettre à jour templates/base.html.twig

  DANS <head>:
  ───────────────────────────────────────
  <link rel="stylesheet" href="{{ asset('assets/styles/dark-mode-responsive.css') }}">
  ───────────────────────────────────────

  AVANT </body>:
  ───────────────────────────────────────
  <script src="{{ asset('assets/js/dark-mode-responsive.js') }}"></script>
  ───────────────────────────────────────

  AJOUTER LE BOUTON TOGGLE (ex. dans navbar):
  ───────────────────────────────────────
  <button class="dark-mode-toggle" title="Mode sombre">🌙</button>
  ───────────────────────────────────────

□ Vérifier l'import (pas d'erreur 404)
  $ bin/console debug:assets


PHASE 5: CONFIGURATION EMAIL (5 min)
════════════════════════════════════════════════════════════════════════════

□ Vérifier .env
  $ grep MAILER_DSN .env
  MAILER_DSN=sendmail://default  (ou SMTP si production)

□ Tester l'envoi d'email
  $ bin/console debug:config mailer

□ Créer un fichier de test d'email (optionnel)
  $ mkdir -p var/mail/
  $ chmod 777 var/mail/


PHASE 6: TESTS DASHBOARD (5 min)
════════════════════════════════════════════════════════════════════════════

□ Aller sur /dashboard
  → Vérifier les KPIs s'affichent:
    - CA Mensuel
    - CA Annuel
    - Total Clients
    - Factures Impayées

□ Si les chiffres sont 0:
  $ bin/console doctrine:query:sql "SELECT COUNT(*) FROM invoice WHERE company_id = 1 AND is_pay = 1"

□ Créer des factures de test si besoin
  $ bin/console doctrine:fixtures:load (si vous avez les fixtures)


PHASE 7: TESTER LES RAPPELS (5 min)
════════════════════════════════════════════════════════════════════════════

□ Vérifier la commande existe
  $ bin/console list | grep payment
  → "app:payment:send-reminders"

□ Tester en dry-run (simulation)
  $ bin/console app:payment:send-reminders --dry-run
  (cette option peut ne pas exister, ignorer si erreur)

□ Lancer réellement
  $ bin/console app:payment:send-reminders
  → Affiche: "✓ Rappel envoyé" ou "✗ Erreur"

□ Vérifier les logs
  $ tail -f var/log/dev.log | grep payment

□ Vérifier la table invoice
  $ bin/console doctrine:query:sql "SELECT id, reference, reminder_sent_at FROM invoice LIMIT 5"


PHASE 8: PLANIFIER LE CRON (10 min)
════════════════════════════════════════════════════════════════════════════

□ Éditer crontab
  $ crontab -e

□ Ajouter (exemple pour Linux/Mac):
  ───────────────────────────────────────
  # Rappels de paiement tous les jours à 9h00
  0 9 * * * cd /var/www/html/saas && \
    /usr/bin/php bin/console app:payment:send-reminders >> \
    var/log/reminder.log 2>&1
  ───────────────────────────────────────

□ Vérifier le CRON est planifié
  $ crontab -l | grep payment
  → Doit afficher la ligne CRON

□ Tester le CRON (attendre que l'heure arrive ou avancer l'horloge système)
  $ /usr/bin/php bin/console app:payment:send-reminders
  (lancer manuellement pour vérifier)


PHASE 9: TESTER LE FILTRAGE (10 min)
════════════════════════════════════════════════════════════════════════════

□ Aller sur /devis ou /invoice
  → Chercher le formulaire de filtrage
  → Vérifier les champs:
    ✓ Recherche
    ✓ Client (dropdown)
    ✓ Statut (dropdown)
    ✓ Date début/fin
    ✓ Montant min/max

□ Tester les filtres
  1. Sélectionner un client
  2. Cliquer "Filtrer"
  → Résultats filtrés par client

□ Ajouter FilteringTrait aux repositories (MANUELLEMENT)
  Si ce n'est pas déjà fait:
  $ grep -r "use FilteringTrait" src/Repository/
  → Doit afficher au moins 1 résultat


PHASE 10: TESTER LES TEMPLATES (10 min)
════════════════════════════════════════════════════════════════════════════

□ Aller sur /templates-documents/
  → Page accessible

□ Créer un nouveau modèle
  1. Clic "Créer nouveau modèle"
  2. Remplir:
     - Nom: "Test Template"
     - Type: "devis"
     - HTML: "<h1>Mon devis</h1>"
     - CSS: "h1 { color: blue; }"
  3. Cocher "Actif"
  4. Soumettre

□ Vérifier le modèle est créé
  $ bin/console doctrine:query:sql "SELECT name, type FROM document_template"

□ Éditer le modèle
  1. Clic sur "Test Template"
  2. Modifier le contenu
  3. Soumettre

□ Supprimer le modèle (test)
  1. Clic "Test Template"
  2. Clic "Supprimer"
  3. Confirmer


PHASE 11: TESTER MODE SOMBRE (5 min)
════════════════════════════════════════════════════════════════════════════

□ Ouvrir l'app en mode clair
  → Vérifier couleurs Shoreline Haze (bleu/crème)

□ Cliquer sur le bouton 🌙 (toggle dark mode)
  → Couleurs invertissent
  → Fond = sombre
  → Texte = clair

□ Rafraîchir la page
  → Mode sombre conservé (localStorage)

□ F12 → DevTools
  → Application → LocalStorage
  → Voir clé "darkMode" = "true"

□ Désactiver localStorage (test)
  → Clic toggle 🌙
  → Rafraîchir
  → Doit revenir à clair (par défaut)

PHASE 13: TESTS SÉCURITÉ (5 min)
════════════════════════════════════════════════════════════════════════════

□ Vérifier les Voters sont actifs
  $ bin/console debug:security

□ Tester accès non autorisé
  1. Créer 2 utilisateurs: User A (Company 1), User B (Company 2)
  2. User A essaie d'éditer facture de User B
  3. Doit recevoir: "Access Denied"

□ Tester voter INVOICE_EDIT
  1. User A crée facture
  2. Facture est NON PAYÉE
  3. Clic "Éditer" → OK
  4. Admin paie la facture
  5. Clic "Éditer" → "Access Denied"

PHASE 15: DÉPLOIEMENT PRODUCTION (10 min)
════════════════════════════════════════════════════════════════════════════

□ Minifier les CSS
  $ csso public/assets/styles/dark-mode-responsive.css -o public/assets/styles/dark-mode-responsive.min.css
  (si csso est installé)

□ Vider le cache
  $ bin/console cache:clear
  $ bin/console cache:clear --env=prod

□ Compiler les assets
  $ bin/console asset-map:compile
  (si vous utilisez asset-mapper)

□ Tester en production
  $ APP_ENV=prod bin/console cache:warmup

□ Vérifier les permissions
  $ chmod 755 var/log/
  $ chmod 755 var/cache/

□ Activer HTTPS si pas déjà fait
  $ # Vérifier Apache/Nginx config


PHASE 16: BACKUP FINAL (2 min)
════════════════════════════════════════════════════════════════════════════

□ Backup de la base de données
  $ mysqldump -u user -p database > backup-$(date +%Y%m%d-%H%M%S).sql

  $ tar czf config-backup-$(date +%Y%m%d).tar.gz .env config/

  $ ls -lh backup-*.sql config-backup-*.tar.gz

TROUBLESHOOTING RAPIDE:

Migrations échouent?
$ bin/console doctrine:migrations:migrate --no-interaction --allow-no-migration

Erreur 404 sur /templates-documents?
$ bin/console debug:router | grep template

Mode sombre ne marche pas?
$ bin/console debug:assets | grep dark-mode

Rappels pas envoyés?
$ bin/console debug:config mailer

Voter bloque l'édition?
$ bin/console debug:security
